# 布局与视觉细节

## 先决定这页让人做什么

拿一屏真实数据，依次指出页面回答什么、哪段信息最先读、主要动作在哪里、次要操作藏在哪儿仍找得到。画或做一张可用的代表页再往其它页面扩展。局部改动沿用上下文里的视觉语言，重做整页时用产品本身决定一种方向，并核对相邻页面能否接上。

| 场景 | 设计和验收 |
|---|---|
| 工具列表或设置 | 先让行之间的关系可扫读。把标题、状态和必要的次要信息排齐，用留白或分隔表现层级。选中、禁用或异常同时有文字、图标或形状提示。 |
| 媒体或内容页 | 让作品或正文先被读到。工具栏、背景和装饰按内容退让。图片裁剪检查真实比例、低清图和加载失败。 |
| 搜索与筛选 | 让用户辨认当前条件、结果和清除方式。没有数据、没有匹配结果和服务出错分别给恰当的下一步。 |
| 窄屏转宽屏 | 让新增空间缩短任务路径，例如列表与详情并排。保留选中项、上下文和可预测的返回。宽屏正文限制舒服的行长。 |

界面用词从任务里来。按钮写动作，错误解释当前发生什么以及用户接下来能做什么。标题能带路就够了，说明只留会影响理解或操作的部分。品牌色、圆角、阴影、卡片和动效各有用途，重复出现的用命名明确的主题角色管理。

## 用真实条件拆穿好看的样例

- 用普通和最难排的一组内容看完成态。长标题、长语言、连续数值、超长列表或图片缺失，按页面实际可能遇到的情况挑。数字比较用一致单位和尺度。
- 在适用的平台试放大字体与显示、键盘焦点、窄窗口和深色时的对比。行高随内容增长，宽度有限时让次要信息换行或移位。主要动作应可触达，键盘弹出时仍能提交或退出。
- Android 触控区域通常至少 48 dp，检查相邻动作的可点击范围不会互相抢占。核对可访问名称、状态、阅读顺序和焦点回到哪里。只靠颜色表意的状态增加可读线索。

验收时并排看同一内容的前后截图，逐项检查对象、操作和状态是否好找好读。如果主要内容或操作仍不易找到，先调整位置和层级，再打磨颜色与圆角。[Android 自适应设计](https://developer.android.com/develop/adaptive-apps/guides/adaptive-dos-and-donts) · [Android 无障碍指南](https://developer.android.com/guide/topics/ui/accessibility/apps)
