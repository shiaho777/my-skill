# Compose 界面工程

## 从用户的任务开始

走一遍实际页面，找到用户在找什么、按什么、哪里会犹豫或失败。已有界面先截图或录下关键过程。新界面拿一组真实内容或脱敏数据做代表页。把当前任务、主操作、返回路径和要保留的行为弄清楚，再动布局和样式。

给页面一个来自产品内容的视觉重点。比如文件工具让人先读到文件名、位置和状态，图片工具优先给作品留空间。用排版、对齐、留白和表面层次决定阅读顺序，少量颜色用来标识品牌、操作和状态。在目标尺寸对比初稿和原图，指出哪些内容或动作变得容易找到。需要新视觉方向或界面还显得杂乱时，读[布局与视觉细节](references/visual-design.md)。

## 把交互做完整

- **操作过程。** 按下、聚焦、选中和禁用都看得出来。提交立即反馈并防重。首次加载、刷新、空结果和失败各有对应表现。刷新保留已可用的内容和位置，失败保留输入并给可行的恢复动作。重要手势提供可见入口，取消时回到原状态，能安全撤销的动作给撤销入口。
- **窗口与输入。** 窄屏时先保内容和必要动作，空间足够时按任务需要增加面板。窗口变化保留选中项和操作上下文。用平台 insets 处理系统栏与键盘。触屏、键盘和鼠标使用各平台惯例，核对主操作在放大字体后仍找得到、按得到。
- **实现取舍。** 看项目实际解析的 Compose 与 Material 版本。复用主题、合适的组件以及它们的焦点和语义。只有现有能力挡住重要需求时才考虑自定义或改依赖。用合适的状态持有者分开业务进度和临时交互，实现放在能维护的位置。需要处理列表、状态恢复、自定义动效或性能时，读[Compose 实现与测试](references/compose-patterns.md)。

## 看效果再交付

构建并运行，优先在目标设备测，模拟器可覆盖适合的场景。亲自看截图、操作主任务和涉及的错误恢复，按发现的问题修一轮再验证。用相同内容比对改前改后。按改动选窗口尺寸、字体、深浅主题、输入方式或键盘遮挡，确认文字、焦点和操作不丢。

手势至少试正常完成、取消和中途再操作。觉得慢时，分别查手指到屏幕反馈的时间、数据完成时间和掉帧，再比较同设备同任务的结果。报告看过的页面和实测场景。预览、构建、模拟器和真机各能证明的范围要说清。
