# Markdown 文档设计

先用仓库内容回答读者的第一个问题。README 通常应让目标读者快速知道产品能做什么、如何开始及如何确认成功。架构文档应让读者定位入口和职责，操作文档应让读者走通任务。局部配图只动相关段落和对应译文。保留原有事实、术语和有效约定，重排时核对锚点和入站链接。

**每张图回答一个问题。** 产品体验用实际截图，结构用组件和边界图，流程用状态或时序图，少量精确数值优先用表格。先把内容和标注写准，再决定媒介、配色和密度。采用目标平台支持的格式，已有真实素材优先复用。需要手绘 SVG 时查 [SVG 配方](references/svg-recipes.md)。

**数字能追溯。** 每项关键指标找得到源码、配置、测量结果或可复跑的命令。对比采用相同口径、环境和版本。估算值用图例和文字明确标注，并说明假设或公式。图表写清单位，关键信息用可复制的正文或表格表达，替代文本描述图想说明什么。

**在读者看到的地方验收。** 检查 README 或实际文档渲染、窄宽度和主题下的可读性，核对链接、图片路径、图注和相对锚点。双语版本对齐事实、图和操作步骤，保留各语言自然表达。对 SVG 可运行 [本地验证器](scripts/validate_docs.py)，传入涉及的 Markdown 文件和 `--assets` 目录。渲染效果和数据准确性仍需核对。

按仓库现有发布约定和用户授权交付。文档改动也适用仓库已有的文档检查和必需 CI。
