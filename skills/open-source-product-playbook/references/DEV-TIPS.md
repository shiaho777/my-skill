# 开发技巧：现代 Web 与 AI 协作

> v1.0 · 2026-11-13 · 通用技巧，与具体产品无关，任何 AI 辅助开发场景可按需取用。
> 来源：拆解 GoogleChrome/modern-web-guidance-src（Apache-2.0；Chrome / Edge / Firefox / MDN 联合维护）+ 本仓库 TECH-STACK.md 方法论。
> 配套：[TECH-STACK.md](./TECH-STACK.md) · [AGENTS.md](./AGENTS.md)（如何写项目 AGENTS.md）。本文件是「运行时层」——自包含、命令式；验证细节在各项目 CI 内部。

---

## 0. 核心事实

LLM 训练数据里充满过时模式，Agent 默认会写旧代码。解法不是更大的模型，而是：**把专家知识做成可检索、可验证的小单元，按需注入上下文，并用评估证明它有效。** 本文所有技巧围绕这一点展开。

---

## 1. 知识交付：写给 AI 读的文档

**1.1 运行时与验证分离** — Agent 只读指南本体；参考实现（demo）、期望清单（expectations）、评分脚本（grader）留在内部做验证。检验标准：指南被单独取出时，不依赖任何其他文件就能执行——自包含、无外链、命令式。

**1.2 只写模型会做错的** — 百科知识模型已有，写进去只烧 token。只写三类内容：反模式（模型默认会犯的错）、决策判据（何时用 A 不用 B）、项目特有约定。用「有指南 vs 无指南」对照实验修剪无效内容。

**1.3 用例导向组织** — 按「我要做什么」命名与归档（style-parent-with-has、fluid-scaling、design-token-reactivity），不按 API 名录。一个平台特性拆成 2–5 个动作导向的开发任务，每个任务一个知识单元。

**1.4 渐进式披露** — 入口文件（SKILL.md / AGENTS.md）只放索引与路由，细节按需检索注入。上下文是稀缺资源，目录不是。

**1.5 每条规则可判定** — 「注意性能」不是规则；「列表 >200 条必须虚拟化，CI 用 5000 条种子数据验证」才是。期望写成可观察断言，直接喂给评分器。

## 2. 评估驱动：没有 eval 的规范只是愿望

**2.1 三阶段流水线** — ① 识别用例（frontmatter 存根即可立项）→ ② 编写指南 + demo + 期望清单（内容贡献者到此为止）→ ③ 工程生成评估、校准评分器、跑对照、出报告。完成标志是「评估落地」，不是「文档写完」。

**2.2 对照实验** — 同一任务跑两组 Agent：带指南 vs 只靠预训练权重。行为差异才是指南的价值证明；无差异的内容删掉。

**2.3 防作弊沙箱** — 评估在一次性 HOME + OS 沙箱中运行，Agent 看不到评分器与仓库源码；参考解来自多个模型家族，避免对单一模型过拟合。

**2.4 行为评分优于文本评分** — 用 Playwright 断言真实渲染、计算样式、DOM 与运行时行为，辅以静态检查；不靠文本相似度。评分器校准设重试上限，仍不稳定就修期望，而非放水。

**2.5 持续校准** — 模型会漂移：夜间回归 + 提示金丝雀（固定任务定期重跑）；期望清单实质修订后，旧评分器自动标记 stale。

**2.6 多基座验证** — 同一指南在两个以上真实应用基座上评估，防止「只在玩具 demo 里成立」。

## 3. 平台特性纪律

**3.1 原生优先阶梯** — 原生 HTML → 原生 CSS → headless 行为 → 带样式库，逐级降级，不一步跳到库。

**3.2 Baseline 三档** — Widely available 直接用；Newly available 用 + 强制轻量降级；Limited / 未发布不用或隔离实验。单引擎稳定特性观察 3 个月（volatile）再纳入默认指南。

**3.3 降级原则** — 轻量 fallback 优于重型 polyfill；没有合理降级时，降级就是「不用」。功能可降级，核心体验不崩塌。

**3.4 时效标注** — 每条特性建议标注「截至日期 + Baseline 状态」。文档没有日期就是定时炸弹。

**3.5 厂商中立** — 核心指南只覆盖多引擎共识（web-features / BCD）；单厂商特性进 opt-in 扩展包并显式标注。知识不属于任何一家浏览器。

## 4. AI 协作流程

**4.1 AGENTS.md** — 仓库根部放 Agent 工作指令：开工前必读什么、按工作流阶段引用哪份规范、边界在哪。

**4.2 技能映射阶段** — 把规范拆成阶段技能（立项 / 编写 / 评估 / 维护），Agent 在哪个阶段读哪份，而不是全程背一本书。

**4.3 贡献可追溯** — AI 产出标注来源：🤖 自主 / ✨ 人类一句话提示 / 🧠 多轮人机协作。评审建议落成 commit 并带 Co-authored-by。

**4.4 评审闭环** — 每条评审线程必须回复 commit SHA 或说明如何采纳；没有闭环的评审等于没评。

**4.5 草稿抑制分发** — 内容带状态字段（stub / wip / blocked），未完成的指南不进检索索引，防止半成品污染下游 Agent。

## 5. 工程习惯

**5.1 轻量工具链** — pnpm + TypeScript + oxlint（快一个数量级的 linter）；单一 CLI 入口聚合所有工作流，避免 npm scripts 蔓延。

**5.2 一条命令启动 + 种子数据** — 贡献者零 API key 跑起来；评估基座应用预置真实感数据。

**5.3 反模式可执行化** — 反模式清单必须配对扫描规则（legacy-scan 思路）：过时 API、硬编码样式、重型依赖、polyfill 滥用，CI 定期扫描出报告。

**5.4 决策留痕** — ADR 记录「为什么这么选」；治理文件（GOVERNANCE / CODEOWNERS / 领域负责人表）让贡献者知道找谁审。

**5.5 分发即 CLI** — 知识打包成确定性、可移植的 CLI（search / retrieve / scan），任何 Agent 无需外部服务即可接入；构建期生成语义索引，运行时按需取。

## 6. 反模式速查

| 反模式 | 后果 |
|---|---|
| 把整本规范塞进每次上下文 | token 爆炸，关键规则被淹没 |
| 指南依赖外链 / 其他文件 | 检索取出后无法执行 |
| 写模型本来就会的内容 | 零收益，纯成本 |
| 文档写完即完成，无评估 | 不知道有没有用，模型漂移后失效 |
| Agent 能看到评分器 | 评估失真 |
| 未标注日期的特性建议 | 过时即误导 |
| 半成品指南进索引 | 污染所有下游 Agent |
| 评审无闭环 | 建议蒸发 |

## 7. 口诀

> **知识做小，按需注入；只写错处，评估证明；原生优先，降级兜底；标注时效，厂商中立；贡献留痕，评审闭环。**
