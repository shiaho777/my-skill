## 0. 我们为什么存在

为爱发电，但绝不假装无所求。

我们求关注、求满足、求追捧，也求简历、求经验、求合作、求机会。把这些说出来不是功利，是诚实——虚伪的「纯为爱发电」会让人不敢要星标、不敢做传播、不敢谈价值，最终做出扭捏的东西。承认所求，才能全力以赴。**我们只做最好的自己。**

**不做平替，不做自慰垃圾。** 每个项目都要能回答三个问题：它创造或整合了什么需求？为什么是现在？为什么是我们？星标与关注不是虚荣，是价值被验证的信号。

**AI 正在清算闭源工具，而开源相反。** 没有实业的单功能工具是时代的眼泪——AI 的逆向与从零重建能力不断进化，闭源工具既无护城河，也谈不上可持续盈利。开源却被 AI 加速：理解门槛消失，贡献量暴涨。**开源社区是 AI 时代最大的红利**；没有资源的普通开发者想把项目做大，社区是唯一杠杆。

**GitHub 是通行证，运营 GitHub 是一份工作。** 那里有最聪明的人和最前沿的科技。把社区运营好、结识优质的人，是一门不需要交易、只用代码讲话的生意。AI 时代的面试看你的 GitHub；足够优秀时，它是能力证明、职业通行证，甚至移民材料。**成为 GitHub 人才——那是年轻人用 AI 创造价值最好的地方。**

## 1. AI 时代的市场本质

**demo 已经泛滥，完成度才稀缺。** AI 让任何人都能在一下午生成一个 demo；稀缺的是工程价值、功能完善性、产品实用性，以及品味与信任。slop 的罪不在生成，而在未经审阅就强加于人；「感受是工作的一部分」——坐下来用它、与它共处，这一层 AI 无法委托。

**护城河不是代码，不是想法，是社区、声誉与完成度。** 代码可被 AI 重建，想法可被瞬间复制；唯有社区归属与长期兑现的声誉不可复制。FOSS 的经济学基于协作而非竞争——声称独占，贡献者就不再出现。

**重点不在努力，在想法。** AI 抹平了实现成本，瓶颈上移到选题、品味与完成度。努力是入场券，选题是天花板——§2 用数据证明这一点。

**前端即传播。** 这个时代极度看重前端：一张好看的界面截图就是传播的主要来源——它语言无关、无需读码、显得真实完成。界面即营销。

**不要痛点思维。** 痛点是工业时代的过去式：找一个烦恼、做小工具、天花板低、被 AI 最先清算。如今的优质新项目无一例外是创造需求或整合需求。**把产品本身做到极致，是唯一的版本答案。**

## 2. 六个项目的共同真理（★ 截至 2026-11-15）

| 项目 | ★ | 一句话 | 需求类型 | 完成度信号 | 传播单元 |
|---|---|---|---|---|---|
| Kazumi | 42.6k | 基于自定义规则的番剧采集 APP | 整合（规则化多源聚合 + 社区规则库） | 1980 commits；F-Droid/Flathub/AUR；SignPath 签名；无遥测 | 6 截图 + 规则生态 |
| dsh-Go | 23.5k | DeepSeek Harness 装进口袋 | 创造（手机上的 coding agent） | 2216 commits；签名 APK；可复现构建；OEM 保活对策；SDK | 吉祥物 GIF + 分享卡片 |
| Folia | 12.7k | Lyrics Reimagined // 辞曲新境 | 整合（多音乐源）+ 创造（歌词 PV 体验） | 3765 commits；测试；mod 签名市场；sync-server | 8 主题预览 + 3 视频 |
| web-to-app | 7.3k | 手机上完整的 APK 工坊 | 创造 + 整合（12 种构建目标 + 设备端运行时） | 1254 commits；CI；10 语言；F-Droid 变体；双语文档站 | 16 张截图 |
| BiliDesk | 664 | 干净、流畅的 B 站第三方 Windows 客户端 | 整合（B 站需求 → 原生桌面） | 286 commits；测试项目；安装器 + 便携版；自动更新 | 1 张 Fluent hero 截图 |
| read-aware | 506 | 带自进化 Agent 的电子书阅读器 | 整合（9 格式）+ 创造（AI 阅读伴侣） | 1890 commits；5 平台发布；E2E 同步；插件市场；CLI | 排版优先 |

把六个项目放在一起，重复出现的不是巧合，是规律：

- **需求先行，且都是大需求。** 没有一个在解小痛点：要么整合平台已有的海量需求（B 站、番剧、音乐、电子书、Web 应用），要么骑技术浪潮创造新行为（口袋 coding agent、手机 APK 工坊、歌词 PV）。
- **完成度是底线，不是亮点。** 安装器、签名、自动更新、多平台、测试、CI、i18n、文档站、可复现构建——这些是入场资格，AI 时代真正稀缺的正是它们。
- **生态把用户变成贡献者。** KazumiRules 社区规则库、read-aware 插件市场、Folia 签名 mod、web-to-app 插件注册表、dsh-Go SDK——长尾需求自助解决，社区成为护城河的放大器。
- **视觉身份、诚实透明、本地优先。** 强视觉身份让人想截图；非官方声明、许可分层、坦承 AI 辅助建立信任；设备端处理、无遥测、E2E 同步是价值观也是资产。
- **一个人 + AI 就能成事。** web-to-app 由作者独立开发（7.3k★）。双语 README、镜像下载、all-contributors、社区运营，都不需要团队。

**关于星标的物理（不是质量评判）。** read-aware 是一件完成度极高的作品——1890 commits、五平台发布、E2E 同步、插件市场、CLI。它与 dsh-Go（23.5k★）、Kazumi（42.6k★）的星标差距，来自需求规模与时机：番剧和 AI agent 的浪潮远大于电子书阅读器，吉祥物的传播力强于克制的排版。**同样的完成度，落在不同的需求规模与时机上，星标会差几十倍。这不是谁做得不好，是选题的物理——完成度是入场券，选题是天花板。**

**平台风险要设计进架构。** 第三方客户端骑平台需求，也继承其政策与 API 风险（Apollo 之死是前车之鉴）。Kazumi 的规则抽象不只是功能，是反脆弱设计——源可切换、社区供规则；Folia 有本地库兜底。单源依赖且无退路，是选题阶段就要否决的。

## 3. 选题方法论

只做后两种思维：

| 思维 | 定义 | 命运 |
|---|---|---|
| 痛点思维（过去式） | 找一个烦恼 → 做小工具 | 天花板低，AI 最先清算 |
| 整合需求 | 分散、已有、海量的需求 → 一个极致体验 | 借需求，不发明需求 |
| 创造需求 | 新技术 / 新行为 → 此前不存在的行为 | 骑浪潮 |

**向外找，五个来源**：大平台缺口（海量需求 + 官方客户端弱）；前沿技术浪潮（AI agent、新设计语言、新 OS 能力——第一批做出极致消费级产品）；行为迁移（已在发生但工具差的行为）；被忽视人群（ADHD 读者、无 PC 用户、特殊网络环境）；「把 X 做到极致」重构（已有品类重做一遍）。

**评分卡**（每项 1–5 × 权重，满分 65；≥45 进入验证，≥55 强候选）。只量想法的真理，不量开发者的自我适配：

| 维度 | 权重 | 一问 |
|---|---|---|
| 需求规模 / 整合空间 | ×3 | 多少人已有这个需求？ |
| 截图传播力 | ×3 | 一张图能否让人想试？ |
| 前沿时机 | ×2 | 在浪潮上吗？窗口还开着吗？ |
| 差异化（非平替） | ×2 | 一句话说清与现有方案的不同？ |
| 极致路径清晰度 | ×2 | 通往完成度的路径清晰吗（AI + 一人即可走通）？ |
| 社区红利 | ×1 | 有现成社区 / 生态可借吗？ |

**一票否决**（命中任一即淘汰）：纯工具无实业；平替无差异；小众痛点自慰；demo 级完成度计划；无传播单元；平台高危无退路。

## 4. 极致的标准

| 维度 | 判据 |
|---|---|
| 工程价值 | 测试 / CI / 签名 / 可复现构建 / 性能预算 |
| 完善性 | PRODUCT.md P0 全项 + 安装器 + 自动更新 + i18n |
| 实用性 | 你自己每天用它（坐下来用、与它共处；demo 验证存在，不验证好用） |
| 传播性 | hero 截图 / GIF + 一句话 pitch + README 转化结构 |
| 前沿性 | 骑当前浪潮，不是 2020 年的品类 |

前三项是入场券，后两项乘以选题是天花板。五维全过才叫优秀开源项目，缺任何一项都只是 demo。

## 5. 传播与增长

**README 即广告。** 病毒式项目的共同结构：logo → 项目名 → 一句话 pitch → badge 行 → hero 截图 / GIF → 一键上手。截图是分享单元——语言无关、无需读码、显得真实完成；GIF 比视频更常被看完；badge 传递健康信号（绿 CI 吸引人，红 CI 劝退人）。

**Trending 靠窗口内的星标速度，不是总数**（社区共识，GitHub 未公布公式；日 / 周 / 月三窗口 + 语言过滤）。topics 与 release 节奏不是 trending 信号，它们作用于搜索、topic 页、watcher 通知等其他发现面。飞轮：trending → 曝光 → 更多星 → 留在 trending。不刷星、不搞投票环。

**渠道各奖励什么**：

| 渠道 | 奖励 | 纪律 |
|---|---|---|
| HN Show HN | 自己的作品 + 可直接试用 + 作者在场 | 无注册摩擦、无落地页；trivial AI 玩具被明确嫌弃 |
| V2EX 分享创造 | 完成的独立作品 + 赠送码 | 短而具体，求拍砖姿态 |
| 少数派 Matrix | 实际工作流价值 | 写整合与体验，不堆功能 |
| awesome-list PR | 长尾引荐流量 | 按各列表规范 |
| PH / X / B 站视频 | 打磨 + demo 视频 | 视觉即内容，build-in-public |
| 即刻 | 短视觉 demo + 真实构建叙事 | 独立开发者氛围 |

semantic-release 自动发布；每次 release 是 watcher 通知 + 重新分享的理由；changelog 弹窗把更新变成留存触点。

## 6. AI 主动构思工作流（从零到一）

用户没有头绪，只说「帮我找一个想法并做到优秀」——这不是幻想。把选题、开发、维护、产品思维讲清楚后，AI 主动向外搜索、构思、验证、执行，是可行的。上限取决于上下文质量，而本文就是那个上下文。

**Stage 0 — 向外找真理，不做自我适配分析。** 不要问用户「你有没有兴趣 / 技能栈 / 账号适合什么 / 能投入多少时间」——这些全是反面教材。**只找自己适合的东西，永远找不到真理**；真理在需求里、前沿里、时代里，不在开发者的自我画像里。三条理念取代问卷：

1. **先找到值得做的东西，兴趣随之而来**——或在做的过程中逐渐培养。兴趣是投入的产物，不是前提。
2. **一个人 + AI 就够。** web-to-app 是作者一人开发的活证据；「需要团队」是伪命题，不构成否决。
3. **AI 主动向外搜索**（§3 五来源），把找到的真理带回来呈现；用户做选择与承诺，不填自我评估表。

**Stage 1 — 构思。** AI 搜索前沿浪潮 + 平台缺口（不只复述用户的话），生成 5–8 个候选，评分卡打分，呈现 top 3，每个附一页 brief：理念 / 需求证据 / 差异化 / 极致点 / 截图概念 / 风险。命中一票否决的直接淘汰并说明——AI 必须有勇气说「这个想法不行」。

**Stage 2 — 验证。** 搜竞品（现有方案为什么没做到极致？）、需求信号、可行性、平台风险与退路。用户拍板后写一页 project brief。不跳过验证。

**Stage 3 — 建造。** 交棒执行层：TECH-STACK（三栈选型）+ PRODUCT（完善性）+ DEV-TIPS（协作）；设计系统按需可选（见 UI-DESIGN，非必选）。垂直切片推进；传播单元先行——最早做出那张 hero 截图，用它持续校准方向。

**Stage 4 — 发布。** README 转化结构 + hero 截图 / GIF + 按 §5 渠道投放 + release。

**Stage 5 — 维护与增长。** 见 §7。每阶段有产出物，门与门之间不许跳。

## 7. 维护与可持续

- **文档化目标与边界**：README / VISION 写清目标、公开 roadmap、真实时间预算；沟通保持公开。
- **Triage 纪律**：让 issue 流动；不打算接受的果断关闭（「No is temporary, yes is forever」）；模板防低质量提交。issue 洪水既是热度也是负担，triage 容量要匹配增长。
- **AI 时代的高吞吐维护**：AI 辅助分诊；替贡献者修好代码再合并并署名；request-changes 是最后手段（它制造贡献者饥饿）；人保留那 5–10% 的品味判断。
- **认可一切贡献**：all-contributors 口径——文档、翻译、设计、报 bug 同样上榜。
- **长期主义**：迭代不重写；不破坏 API；文档好到「你不需要我」；对新人友好；近乎过度的透明。
- **Burnout 边界**：每周时限，休息先于倦怠。社区是马拉松。
