# 开源产品设计规范：从开发者思维到产品思维

> v1.1 · 2026-11-16 · 通用，与具体产品无关。
> 配套：[TECH-STACK.md](./TECH-STACK.md)（三栈选型）· [DEV-TIPS.md](./DEV-TIPS.md)（怎么协作）· [AGENTS.md](./AGENTS.md)（如何写项目 AGENTS.md）。设计系统可选（见 [UI-DESIGN.md](./UI-DESIGN.md)，非必选）。本文回答：**做成什么样才算一个完整的开源产品**。
>
> **AI 必读**：本文是运行时层，条目可直接执行、可判定。按 P0 / P1 / P2 分级落地：**P0 缺失 = 产品不完整**。文中所有联系方式、社区入口均为可配置槽位，不是硬编码需求。

---

## 0. 核心认知

**开发者思维**问：功能对不对、代码好不好、性能够不够。
**产品思维**问：用户旅程完不完整、信任能不能建立、社区能不能循环、贡献有没有入口、生命周期有没有交代。

开源产品的特殊性：**用户即潜在贡献者，界面即社区漏斗，透明即功能。**

生命周期漏斗（每个阶段对应本文条目）：

```
发现 → 安装 → 首五分钟(§1) → 日常使用 → 更新(§5) → 反馈(§4) → 贡献(§4) → 传播
```

核心资产是**信任**：开源没有营销预算，信任来自透明（§6）、克制（不纠缠用户）与兑现（更新有交代）。

气质基调：真诚、不端着、有社区感。引导页可以说「初次使用，希望你玩得开心」，而不是「欢迎使用本系统」。

## 1. 首次体验（P0）

- **引导页**：这是什么（一句话）→ 能做什么（3 个核心能力，配图/图标）→ 情感一句（「初次使用，希望你玩得开心」）→ 社区与作者入口。3–5 屏封顶，**可跳过**，设置里可回看。
- **零强制**：不强制登录、不强制权限、不强制联网。本地优先产品离线必须可用。
- **空态即引导**：每个空列表回答「这里会有什么 + 如何开始」，给主动作按钮；提供演示数据/示例内容（见 TECH-STACK §4 种子数据）。
- **权限即时请求**：用到才要，先给理由（按产品替换，如「需要存储权限来扫描你的音乐」），拒绝有降级路径。完整引导页设计见 §1.1。
- **首装 ≠ 更新**：首装走引导；更新走 changelog 弹窗（§5），不重复引导。

### 1.1 权限引导页设计（手把手开权限）

**为什么需要**：系统弹窗只问「允不允许」，不解释为什么、怎么开。许多权限（Android 无障碍、macOS 屏幕录制）必须手动进系统设置才能开；开源应用常需敏感权限，只能靠透明建立信任。手把手引导既降低拒绝率，也是信任资产。实证：dsh-Go（Android 无障碍 / Shizuku / ADB）、dogsc（macOS 屏幕录制 / 辅助功能）。

**核心单元——每个权限六件套**（dsh-Go 实证）：

```
命名行 → 直达按钮 → 精确系统屏 → 白话理由 → 验证动作 → 失败分支
```

不是「去设置里开」，而是「点这个按钮跳到那一页 → 按这几步开 → 开完点验证 → 没开成这样办」。

**设计原则**：

1. **必需 vs 按需分离**：核心权限前置引导（dogsc：屏幕录制 + 辅助功能），可选权限用到才要（麦克风 / 摄像头；dsh-Go 手机操控权限只在启用该功能时请求）。不要一次全要。
2. **分层独立授权，同意不泛化**：每层独立的风险说明 + 授权 + 验证；反复区分「授予 X」与「允许 Y」，不让一次同意被泛化成全部授权（dsh-Go）。
3. **先理由后请求 + 数据透明**：先说明读什么、发给谁，再「同意并开启」；敏感数据先打码（dsh-Go：屏幕文字发给模型、银行卡/身份证先掩码）。
4. **干跑验证再信任**：给一个不产生副作用的测试动作（dsh-Go「读一下当前屏幕」，明确不发给模型），让用户安全确认权限生效。
5. **分级确认 + 安全默认**：每次询问（默认）/ 本任务免确认 / 始终免确认（需额外确认）；敏感动作默认交还用户；支付/银行类默认不碰；放宽须「我知道风险，仍然修改」。
6. **拒绝有降级，失败有分支**：拒绝不死胡同（dogsc Gatekeeper「仍要打开」+ 支持链接；dsh-Go 远程模式跳过本地运行时）；渠道失败 / 系统拒绝 / 响应但无权限分别提示，拒绝不误标为「未连接」。
7. **渐进披露**：高级选项（手动配对、排障）默认折叠；折叠不改授权状态；连接错误始终可见。
8. **风险分级 + 摩擦确认**：最危险项须读风险页 + 长按约 1.5s 确认，不可任务中开启，一键关闭，badge/锁标识当前状态（dsh-Go 解除限制）。
9. **状态检测 + 可回看重授**：检测授权状态（✓/✗）；引导可从设置回看；权限被撤销后有重授路径。
10. **平台与 OEM 适配**：不同平台机制不同（见下表）；品牌特定指引（「无障碍开关点不动？」）；ROM 菜单名差异要覆盖。
11. **隐私开关进引导**：遥测等可在首跑引导中关闭（dsh-Go）。

**引导流骨架**：

```
理由屏（是什么 / 为什么 / 数据去哪）
  → 步骤图 + 直达设置按钮
  → 系统授权
  → 检测授权状态
  → 干跑验证
  → 成功进入 / 失败降级或重试
```

**跨平台权限要点**：

| 平台 | 典型权限 | 引导要点 |
|---|---|---|
| Android | 无障碍 / Shizuku / self-ADB / 通知 / 安装未知来源 / 后台弹出 | 多需手动进设置；OEM 电池与受限设置适配；品牌特定指引 |
| macOS | 屏幕录制 / 辅助功能 | 必须手动进系统设置；未公证的 Gatekeeper「仍要打开」fallback |
| iOS | 相机 / 麦克风 / 通知 | 系统弹窗，需用户手势触发；特殊场景才涉开发者模式 |
| Web | camera / mic / notification / geolocation | 浏览器 API，需用户手势触发；拒绝后给降级 |

**反模式**：一次全要权限；只弹系统窗不给理由；拒绝即死胡同；无重授路径；隐瞒数据去向；把「授予某权限」泛化成「允许所有」。

## 2. 设置页信息架构（P0 骨架）

| 分区 | 条目 | 级别 |
|---|---|---|
| 关于 | 图标+名称+版本+一句话 / README / 开源协议 / 第三方许可 / 作者 | P0 |
| 社区与支持 | 社区入口 / 意见反馈 / 参与贡献 / 感谢贡献者 / 赞助（可选） | P0 |
| 更新 | 自动检查开关 / 立即检查 / 更新通道 / 跳过此版本 / 更新日志 | P0 |
| 隐私与数据 | 隐私声明 / 网络请求说明 / 崩溃报告开关 / 导出导入备份 | 声明 P0 / 数据 P1 |
| 外观与行为 | 主题 / 动态取色 / 对比度 / 语言 / 动效减弱 | P0（设计系统可选，见 TECH-STACK §3） |

原则：关于区不是杂物间，是**产品的身份证 + 社区的会客厅**。

---

## 3. 关于体系（P0）

- **身份卡**：项目图标 + 名称 + 版本号（可点击复制/查看构建信息）+ 一句话介绍。
- **README 内嵌**：拉取 GitHub README 渲染为 Markdown（实现见 §8）；离线缓存；渲染失败降级为链接跳转。
- **开源协议**：展示仓库 LICENSE 全文（Unlicense / MIT / GPL……以仓库为准），专属页面或 bottom sheet，等宽字体。
- **第三方许可清单**：所有依赖的 license 汇总页——**法律必需，不是可选**（Apache / GPL 的署名义务）。
- **作者信息**：X / 微信 / QQ / TG / 邮箱 / 博客，**全部可配置**；暴露哪些由作者决定，产品只提供槽位。联系入口带「复制」，而非只能跳转。

---

## 4. 社区与支持（P0）

- **社区入口**：TG 群 / QQ 群 / Discord / Matrix / GitHub Discussions，按项目实际配置。QQ/微信群用二维码：**本地生成**（不经过第三方 QR API），标注有效期，过期可刷新。
- **意见反馈**：GitHub Issue 跳转（模板预填版本/平台/复现步骤）；应用内反馈可选，附日志导出——**用户审阅后才发送**。先链「已有 issues」减少重复。
- **参与贡献**：GitHub PR / CONTRIBUTING / good first issues 跳转；说清「不会代码也能贡献」（文档 / 翻译 / 设计 / 报 bug）。
- **感谢贡献者**：contributors 列表跳转 + 应用内头像墙（GitHub contributors API）；采用 all-contributors 口径，**非代码贡献同样上榜**。
- **赞助**：GitHub Sponsors / Open Collective / 爱发电，入口常驻但**绝不弹窗纠缠**。

---

## 5. 更新体系（P0）

- **检查**：GitHub `releases/latest`（稳定通道）/ `releases`（prerelease 通道，opt-in）；ETag 条件请求 + 本地缓存（未认证限流 60 次/小时/IP，304 不计额）；semver 比较；自动检查默认开、可关、可手动。
- **内置下载**：进度可见；**校验和 / 签名验证**（Tauri updater 签名 / PWA service worker 流程）；失败可重试、可跳转浏览器下载。
- **更新后弹窗**：本地检测 lastSeenVersion 变化 → 弹 changelog（Markdown 渲染，sanitize）；**每版本只弹一次**，可关闭，附完整 release 链接；「跳过此版本」对检查生效。
- **渠道纪律**：F-Droid 构建禁用内置更新（与其更新机制冲突）；商店构建同理。
- **可选公告**：远程 notice 系统需先过隐私评审（§6），默认不做。

---

## 6. 信任与透明（P0）

- **隐私声明**：收集什么（最好为零）、存哪里、发往哪；**网络请求清单**可查。遥测默认关，opt-in 且可审。
- **权限说明**：每个权限一句话理由，设置里可查。
- **可验证**：发布附校验和 / 签名；可复现构建（reproducible builds）为 P1 目标；SECURITY.md 安全上报通道。
- **克制**：无广告、无暗黑模式、无 star-ware（「给星解锁」）、无评分纠缠、无强制订阅。

---

## 7. 数据主权与可及性（P1）

- **导出 / 导入**：开放格式（JSON / CSV / 标准媒体格式），备份 / 恢复，schema 有文档——**无锁定是开源承诺的一部分**。
- **i18n**：应用内语言切换；翻译走 Weblate / Crowdin；本文所有字符串进 i18n，不硬编码。
- **可及性**：RTL、字体缩放、reduced-motion（见 UI-DESIGN §4 护栏）。

## 8. 设计系统映射与实现要点（以 MD3 为例，可选）

**产品表面 → 设计系统组件（以 MD3 为例）**：

| 表面 | 组件 |
|---|---|
| 引导页 | 全屏 dialog / 分页 + display 字级 + hero 图形 |
| 身份卡 / 设置条目 | ListItem（leading 图标）+ tonal card |
| 更新弹窗 | Dialog + Markdown 渲染 + text button（跳过 / 详情） |
| 贡献者墙 | 头像网格 / avatar chips |
| 协议 / README | 专属页或 bottom sheet，等宽 / 正文排版 |
| 社区二维码 | Dialog + 本地图像 |
| 外链跳转 | 菜单项 + 「即将离开应用」确认（可选） |

**GitHub API 端点**（未认证可用，注意限流与缓存）：

| 用途 | 端点 |
|---|---|
| 更新检查 | `GET /repos/{owner}/{repo}/releases/latest` |
| 贡献者 | `GET /repos/{owner}/{repo}/contributors` |
| README | `GET /repos/{owner}/{repo}/readme`（Accept: raw） |
| 协议 | `GET /repos/{owner}/{repo}/license` |

**实现纪律**：

- Markdown 渲染必须 sanitize（DOMPurify）；README 相对链接 / 图片转 absolute raw；离线缓存兜底。
- 版本号 semver 比较；lastSeenVersion 本地持久化。
- 二维码本地生成；外链走系统浏览器。
- 所有文案进 i18n；所有开关有默认值且尊重用户选择。

## 9. 分级总清单

**P0（缺 = 不完整）**：引导页（可跳过）/ 空态引导 / 权限引导页（敏感权限手把手，§1.1）/ 身份卡 / README / 协议 + 第三方许可 / 作者槽位 / 社区入口 / 反馈（issue 模板）/ 贡献入口 / 贡献者 / 更新检查 + 内置下载 + changelog 弹窗 / 隐私声明 / 无强制登录权限

**P1（优质线）**：数据导出导入 / i18n + 翻译平台 / 崩溃报告 opt-in / 可复现构建 / 赞助入口 / 远程公告（隐私评审后）/ 演示模式

**P2（加分）**：应用内反馈带日志 / 贡献者头像墙 / 路线图公开 / 功能投票（reactions）/ 社区 FAQ 内嵌

## 10. 反模式

| 反模式 | 后果 |
|---|---|
| 强制登录 / 权限才能用 | 首五分钟流失 |
| 引导不可跳过、更新重复引导 | 不尊重用户 |
| 每次启动无缓存查更新 | 触发限流，检查失效 |
| README / 公告渲染不 sanitize | XSS |
| 第三方 QR API 生成群二维码 | 泄露 + 追踪 |
| 弹窗纠缠评分 / 赞助 / 给星 | 信任破产 |
| 静默遥测 | 开源信任核心崩塌 |
| 第三方许可缺失 | 法律风险 |
| 社区死链 / 二维码过期 | 社区漏斗断裂 |
| 反馈 mailto 无上下文 | 无效反馈循环 |
| 数据不可导出 | 违背开源承诺 |

## 11. 口诀

> **首五分钟定留存，关于页是身份证；更新有交代，反馈有闭环；贡献有入口，透明即功能；克制不纠缠，社区自然来。**
